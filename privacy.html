Data practices

Privacy policy

Draft prepared 12 October 2026 · Not yet adopted

Owner review is required before this policy is published as the application's policy. Retention, provider settings and the support contact must be confirmed against the running installation.

1. Application and purpose

Jarvis is a personal assistant maintained by JRAHADMIX for the owner's own use. Google data is used to provide email review, reply drafting, daily briefings, calendar summaries and document lookup.

2. Google data accessed

  • Gmail: message headers, senders, recipients, dates, subjects, message bodies and thread context needed for the configured features. Attachment names and metadata may be read; the current mail worker does not download attachment contents.
  • Calendar: calendar and event information such as titles, dates, times and descriptions needed for briefings and review.
  • Drive: file search results, metadata and document information requested through the enabled read-only tools.

Requested permissions: gmail.readonly, calendar.readonly and drive.readonly. Access occurs after the owner's Google authorization, including configured scheduled briefings and notifications.

3. Processing and recipients

Jarvis processes and stores working data on the owner's computer. Relevant Google content can be included in requests to the Anthropic API to generate summaries, analyses and reply drafts. Selected results and notifications can be sent to the owner's configured Telegram conversation. These are external services; processing is not exclusively local.

This static information website is hosted by GitHub Pages. Its files contain application information only. No Google account data or OAuth credentials are included in the website. GitHub may process ordinary website request information under its own privacy statement.

4. Storage and deletion

The private installation can retain OAuth credentials, session history, source snapshots, drafts, reports, logs and backups. Revoking Google access stops future authorized requests but does not itself erase previously saved copies.

Before adoption: the owner must confirm retention periods and the procedure for deleting local records, backups and Telegram copies. Anthropic retention and training settings must also be checked; this draft does not claim zero retention or that all processing stays on the owner's device.

5. Control and security

The owner can revoke Jarvis access in Google Account settings and stop scheduled features in the private installation. OAuth tokens are stored in a restricted local file. Credentials must not be committed to this public repository.

6. Permitted use commitment

The proposed policy limits Google data use to the assistant features described above. It prohibits selling Google user data, using it for advertising or using it to train generalized AI models. Jarvis's use and transfer of information received from Google APIs must adhere to the Google API Services User Data Policy, including its Limited Use requirements. The owner must verify the implementation and provider configuration before adopting this commitment.

7. Contact and changes

Maintainer: JRAHADMIX. A public support email must be confirmed before final publication. Changes to Google data use must be disclosed before the changed processing begins.
